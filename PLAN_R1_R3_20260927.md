## 1. Schemat steps.json + przykład

### Cel

`steps.json` to kanoniczny, samowystarczalny snapshot całego stanu pipeline po `vtd run` — zawiera zarówno suche dane kroków (ManualStep), jak i wzbogacone dane LLM (enriched_data). Dzięki temu `vtd rerender` nie musi rekonstruować danych z MD/PROMPT.

### Schemat (JSON Schema uproszczony)

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "VTD Steps",
  "type": "object",
  "required": ["version", "steps", "enriched_data"],
  "properties": {
    "version": { "type": "string", "description": "Wersja schematu, np. '1.0'" },
    "steps": {
      "type": "array",
      "items": {
        "type": "object",
```

## 3. Plan testów (minimum 4 przypadki)

Wszystkie testy w `tests/test_rerender_docs.py` (rozbudowa istniejącego pliku) i ewentualnie nowy `tests/test_steps_store.py`.

### T1: `test_steps_store_save_and_load_roundtrip`
**Co testuje:** `save_steps_json` → `load_steps_json` round-trip bez utraty danych.  
**Setup:** 2 ManualStep z mockowanymi framepath (tmp_path), enriched_data z przykładu.  
**Assert:** `load_steps_json(tmp_path)["steps"][0]["step_number"] == 1`, `["enriched_data"]["meta"]["document_status"] == "DRAFT"`.  
**Plik:** `tests/test_steps_store.py`

### T2: `test_steps_store_duplicate_step_number_raises`
**Co testuje:** walidacja unikalności numerów kroków przy zapisie.  
**Setup:** 2 ManualStep z `step_number=1`.  
**Assert:** `pytest.raises(ValueError)` lub `AssertionError`.  
**Plik:** `tests/test_steps_store.py`

### T3: `test_rerender_uses_steps_json_when_present` (R1)
**Co testuje:** gdy `steps.json` istnieje w output_dir, rerender go używa zamiast parsowania MD/PROMPT.  
**Setup:** tmp_path z minimalnym `steps.json`, `INSTRUKCJA.md` z innymi krokami (pułapka), `PROMPT_DLA_AGENTA.txt` pusty.  
**Assert:** wygenerowany INSTRUKCJA.md zawiera tytuł z `steps.json["enriched_data"]["steps"][0]["title"]`, a nie tytuł z pliku MD.  
**Mock:** `render_markdown_manual`, `render_html_manual`, `render_docx_manual` — przechwycone spy.  
**Plik:** `tests/test_rerender_docs.py`

### T4: `test_rerender_fallback_without_steps_json` (backward compat)
**Co testuje:** gdy `steps.json` nie istnieje, rerender działa po staremu (istniejąca logika PROMPT/MD).  
**Setup:** tmp_path BEZ steps.json, z PROMPT_DLA_AGENTA.txt zawierającym znaczniki [HH:MM:SS].  
**Assert:** wywołano `_timestamps_from_prompt` (lub wynik jest zgodny z PROMPT), NIE zgłoszono FileNotFoundError.  
**Plik:** `tests/test_rerender_docs.py`

### T5: `test_rerender_generates_docx` (R3)
**Co testuje:** `rerender_output_dir` generuje INSTRUKCJA.docx.  
**Setup:** tmp_path ze steps.json lub INSTRUKCJA.md, mock `render_docx_manual` zwracający tmp_path/"INSTRUKCJA.docx".  
**Assert:** `render_docx_manual` wywołany dokładnie raz; wynikowy słownik z `rerender_output_dir` zawiera klucz `docx`; backup `.bak.<ts>.docx` tworzony gdy plik istniał.  
**Plik:** `tests/test_rerender_docs.py`

### T6: `test_rerender_docx_backup_created_if_exists` (R3)
**Co testuje:** istniejący INSTRUKCJA.docx dostaje backup `.bak.<ts>.docx` przed nadpisaniem.  
**Setup:** tmp_path z istniejącym `INSTRUKCJA.docx` (pusty plik + steps.json).  
**Assert:** po rerender w tmp_path istnieje plik `INSTRUKCJA.bak.*.docx` (glob).  
**Plik:** `tests/test_rerender_docs.py`
